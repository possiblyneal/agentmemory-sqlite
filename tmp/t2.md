## What to build

This fork stops taking its engine-facing vocabulary from an external package and owns it instead. The types every function signs its registration with — the SDK handle, the API request shape, and the trigger-action constructor — are defined in this repository, matching what the in-process Engine already provides.

Nothing changes behaviour and nothing is removed yet. Both the old and new forms exist side by side so that every existing caller keeps compiling untouched. This is the expand half of an expand–contract sequence; the call sites move in later tickets and the old form is deleted at the end.

Per ADR 0001, these types describe the in-process Engine only. Do not reproduce parts of the external surface that exist solely to serve the child-process runtime.

## Acceptance criteria

- [ ] The repository defines its own engine-facing types, covering everything the existing call sites import: the SDK handle used to register functions and triggers, the API request shape, and the trigger-action value used when a trigger fires with no payload.
- [ ] The new types are satisfied by the in-process Engine's existing SDK object without changes to it.
- [ ] No existing file is modified to use them yet; the whole suite passes unchanged.
- [ ] The build produces no new warnings and the external package is still installed and still working.

## Blocked by
