## What to build

This fork collapses to a single Engine. The child-process runtime, the selector that chose between the two, the sharded index persistence that only that runtime reached, and the payload frame guard that guarded its wire limit are all deleted. The external engine package stops being a dependency; function registration and dispatch become direct in-process calls.

Nothing the Operator uses depends on any of it. Embeddings already persist in the in-process Engine's own vector table, and the keyword index is rebuilt from stored content at boot — so this removal recomputes no embeddings and costs nothing at the next start. The index shards the deleted code wrote become permanently unreadable; deleting them from disk is a separate ticket.

The `AGENTMEMORY_ENGINE` variable is read and ignored rather than rejected, so the Operator's existing environment file keeps loading untouched.

This is the contract half of the expand–contract sequence, and it is the decision recorded in ADR 0001. Tests belonging to deleted modules are deleted with them, not skipped.

## Acceptance criteria

- [ ] The external engine package is no longer a dependency and nothing imports it.
- [ ] The child-process runtime, the Engine selector, the sharded index persistence module, and the payload frame guard are gone from the source tree.
- [ ] Setting `AGENTMEMORY_ENGINE` to any value — including one that used to select the removed runtime — starts the daemon normally and does not warn or fail.
- [ ] The daemon starts, reaches readiness, and serves every REST endpoint and MCP tool exactly as before.
- [ ] Recall returns the same results for the same query as before the removal, against the same store.
- [ ] Booting recomputes no embeddings that would not have been recomputed before.
- [ ] The suite passes with the deleted modules' tests removed rather than skipped, and no remaining test is skipped to accommodate the removal.
- [ ] No conditional on which Engine is running remains anywhere in the source.
