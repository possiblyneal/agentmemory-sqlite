## What to build

A failure to read the Graph Snapshot stops destroying it. Today the read helper swallows every error and hands back an empty graph; Extraction then proceeds as though the graph were genuinely empty and writes that empty view back over the stored Snapshot, losing the real one and zeroing its statistics. It does not even mark the result as suspect, so the damage looks like a clean write.

Instead, a read failure aborts that batch of Extraction before its first write. The stored Snapshot is left exactly as it was. The batch's extraction is lost and will be retried when the next Session produces Observations — it is not retried in place, so a persistent fault cannot spin.

The Operator finds out this happened from the log, at warning level, rather than by noticing absent data later.

## Acceptance criteria

- [ ] When the Snapshot cannot be read, Extraction for that batch performs no writes at all — not to the Snapshot, not to Entities or Relations.
- [ ] The stored Snapshot is byte-for-byte unchanged after such a failure, including its statistics.
- [ ] The failure is logged at warning level and identifies itself as a Snapshot read failure.
- [ ] The failure does not crash the daemon or leave the Extraction path unusable for the next batch.
- [ ] A genuinely absent Snapshot — first run, nothing stored yet — is still treated as an empty graph and proceeds normally. Absence is not failure.
- [ ] A subsequent batch that reads the Snapshot successfully proceeds as normal, with the preserved Snapshot as its base.
