## What to build

Provenance on an Entity or a Relation stops growing without limit. Every site that writes it keeps only the fifty most recent Observation ids and discards the rest, so a row's size stops tracking how often the Agent happens to mention it.

Today nothing bounds this at all. Two merge paths union ids forever, a second union in the temporal Extraction path bypasses the merge helpers entirely, and the two creation writes store a whole Extraction batch uncapped. All four are the same defect and all four are in scope here.

Ids are appended in chronological order, so keeping the newest is a tail slice of what is already there. The bound is a single named value with an `AGENTMEMORY_`-prefixed environment override, defaulting to fifty.

This ticket bounds writes going forward only. Rows already over the bound are repaired in a later ticket.

## Acceptance criteria

- [ ] Merging an Entity whose Provenance would exceed the bound keeps the newest ids up to the bound and no more.
- [ ] The same holds for Relations.
- [ ] The same holds for the temporal Extraction path, which currently unions ids without going through the merge helpers.
- [ ] Creating an Entity or Relation from an Extraction batch larger than the bound stores no more than the bound.
- [ ] A row under the bound is left exactly as it was, with its ids in their existing order.
- [ ] The bound is a single named value used by every write site, overridable from the environment, defaulting to 50.
- [ ] An Agent recalling a capped Entity still receives usable Provenance.
