## What to build

Every module under the functions directory — the large majority of the call sites — takes its engine-facing types from this repository instead of the external package. This is a mechanical migration: the types are structurally the same, so no behaviour changes and no logic moves.

The trigger-action value is a runtime value rather than a type, so those call sites need the local value substituted, not just the import path rewritten. Everything else is type-only.

The old form still exists throughout this ticket, so the suite stays green from start to finish. This is one migrate batch of an expand–contract sequence.

## Acceptance criteria

- [ ] No module under the functions directory imports from the external engine package.
- [ ] Call sites that construct an empty trigger action use the local value and behave identically.
- [ ] The full suite passes, with no test modified to accommodate the change.
- [ ] No function's registered name, payload shape, or return shape changes.
- [ ] The external package is still installed and other directories still use it.
