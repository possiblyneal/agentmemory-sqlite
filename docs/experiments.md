# Experiment ledger

Every hypothesis tested against this repo's Goal (`CLAUDE.md`), kept, rejected or
inconclusive, so a tried lever is not run again. Read it before choosing a lever. Add a row
when an experiment ends; never delete a rejected row. The numbers and method live in the
linked scorecard (`docs/benchmarks/`) or issue; this file is the index and the verdict.

A rejected or inconclusive row names what would justify a retry. Rerun it only when that
condition holds, and link the new row to the old one.

## Sources

A hypothesis comes from one of these, named in the Source column:

- **history** — the Operator's own Sessions: replay misses, the decision key, Missed
  Injections, the live daemon's logs and store (read-only)
- **repo** — another memory system's code ([`research/memory-repos.md`](./research/memory-repos.md))
- **paper** — a published result ([`research/memory-papers-survey.md`](./research/memory-papers-survey.md)), by arXiv id
- **incident** — a defect seen in operation

## Verdicts

- **kept** — shipped on a measured gain that did not lose on `typical` or holdout
- **rejected** — measured no gain, or a loss; do not retry unless the Retry if condition holds
- **inconclusive** — the measurement could not decide (too few items, noise, a broken run)
- **finding** — a measurement that tests no lever but changes what is worth trying
